# CodeProof Main Windows desktop

The main desktop opens with Connect your project. It has no offline sample action or bundled PracticeWorkspaceService. The clearly labelled CodeProof Demo App folder preserves the previous demonstration application separately.

Connect using an explicitly selected filesystem folder, CodeProof backend pairing token and its loopback port. Blank folders are rejected before connecting. This port belongs to CodeProof, not a target application's server. The backend starts with python -m backend and exposes /health and authenticated /v1 sessions.

Project inspection uses Guardian snapshots. Explicit AI analysis sends selected redacted context to the configured provider after consent. Investigation, explanation evaluation, patch review, managed-copy application, measured Docker validation and release-readiness evidence remain available. No controlled demo incident is advertised by the main backend.

Keep all Windows runtime DLLs and the data directory beside codeproof_desktop.exe. Native builds require Flutter/Dart and the Visual Studio C++ desktop workload. The user approved isolated native Flutter checks and a Windows rebuild for this separation; selected project code remains Docker-only.

Synthetic practice fixtures live under test/support for isolated widget regressions. They are not imported by the main lib/main.dart application and are not compiled into its runtime. Main startup/blank-path behavior has a dedicated widget regression; backend route isolation and Guardian-before-selection gates have dedicated Docker-tested regressions.
